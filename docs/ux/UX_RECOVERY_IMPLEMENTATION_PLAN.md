# Windows Studio 产品恢复实施方案

**提案 v1 · Project批准前不得实施 UX-R1–R4。** UX-R0本轮只做文档/证据，不修改生产代码。原产品 **PRODUCT HOLD / NOT ACCEPTED**，CP4仍未完成，不能称RC。

## 1. 恢复目标与范围裁决提案

交付目标是用户可以在一个应用中完成“设计→生图→找回/比较→排版打码→交付→下次继续”，并通过真实应用内升级保全作品与凭据。验收单元是 [W1–W5故事](UX_R0_WORKFLOW_AND_LAYOUT.md)，不是菜单数量或单个按钮。

建议Project批准 [GUI合同](UX_R0_WORKFLOW_AND_LAYOUT.md) 及 [矩阵](UX_R0_PARITY_MATRIX.md) 完整继承恢复目标（包括T20小人书/PDF）；能力状态不能视为批准。最低充分范围包括真实账户/设计/NAI、完整结构化Prompt/角色/Tag/图像引导/历史回用、可用的文字与打码编辑、批次预览复制保存、metadata/完整比较、备份恢复及完整CP4。P17后处理/P18反推/P19图像相关角色卡导入不能因首个文生图成功就遗漏；实现中按权威模型能力提示支持范围。

**无默认缩减：** 最新Issue #4完整继承要求覆盖旧需求中TypeSet“候选”标注。富文本、小人书动态页面、连续页面和整册PDF都在目标内；任何Release排除必须有用户明确范围批准，Project不能用旧助手提案代替。Desktop之外的聊天/Android/Server功能不混入本轮；统一多API档案、持久图库、完整比较属于Suite新增能力，不能冒称来源P7已具备。

UX-R0不以美术偏好不明为由向用户分发几十道问题。Project一次审查结构、最小范围和测试合同后，再给连续实现批准；实现中的普通错误由Codex修复重测，主观可用性留给一次固定包集中验收。

### 真实请求预算与证据

既有用户授权为每小时不超过12次实际调用、相邻至少300秒。本轮不调用。后续只在Project实施批准有效且该授权未撤回时使用真实路径；密钥仅受保护存储，不写合同、日志或仓库。LLM设计一次用户动作可能有planner/design等多次实际请求，每次都计数并排队，包含可能的重试/参考编码，不是一次按钮计一次。等待显示原因和可取消状态；不以多账号或多进程绕过限制。

## 5. UX-R4 / CP4 不可降级合同

遵守 [05_UPDATE_AND_RELEASE](../05_UPDATE_AND_RELEASE.md) 与 [UPDATE_A_B_PLAN](../rc/UPDATE_A_B_PLAN.md)。必须实际从安装版本A的应用内触发B更新；不是文件复制故障lab，也不是单独TUF测试。

1. 隔离环境预装A，合成原件/工程/设计历史/测试凭据；记录安装包、版本、源码、数据和凭据引用指纹（不输出秘密）。测试签名仅该环境，不能生成正式发行私钥或改系统信任。
2. A发现B，用户确认下载；验证可信元数据/签名、产品平台、大小hash、过期/回滚/freeze、信任轮换；SHA校验不能替代来源身份。
3. 保存、排水，活动任务明确等待/取消，超时不提前释放锁；关闭后真实安装并启动B。版本、数据schema/协议版本分开；迁移失败保全备份与旧状态。
4. B核验原始bytes、工程/Recipe/历史、账号别名与受保护凭据可用性；测试凭据仅在受控本地服务验证解密和引用，不能因退出后重进成功推断真实账号迁移。
5. 覆盖离线、坏签名/错平台、回滚/过期元数据、空间不足、下载中断、安装失败、迁移中断、B启动失败、活动写入/任务。保留失败前后证据；显示真实成功/失败/恢复结果，不统一报更新完成。

Windows首版必须完整执行；Android/Server首版安全更新要求继续保留在原合同，本恢复任务不提前实现它们也不删除它们。

## 6. 一次集中真人验收的进入条件与安排

先完成工程门槛、可安装包身份、五条故事自检和已知缺口清单，再请求一次集中Windows验收。包中准备隔离样例工程/metadata/两图比较/字体样例/备份，不读真实图库。用户不必重复已通过的同源基础项；改动影响窗口/输入等时只纳入有理由的回归。

集中顺序：W1创作与候选应用→W2导入→W3比较→W4排版批次导出/小人书整册→W5保存重开/恢复与更新体验。预先说明哪些步骤有真实费用、哪些是合成、预计等待来自300秒限制；所有可测项在一次会话中提供，用户可标NOT TESTED和自由反馈，不强迫逐按钮提交。

人工重点：CCB工作流是否自然、身份/费用是否理解、图像结果是否找得到、排版质量/手感、批量范围与输出是否可预期、恢复与更新结果是否清晰。布局截图和可靠自动化只签各自证据，不签主观质量。用户未通过则保持PRODUCT HOLD；不把失败拆成许多“可忽略小问题”降门槛。
