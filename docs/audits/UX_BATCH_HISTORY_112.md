# Preview112：批次编辑撤销/重做

用户指出111撤销按钮反复进行同一组操作，要求正常重做、导航键与右键入口。根因是单槽历史每次undo交换当前/旧分组，实为toggle。

改为50步before/after栈，包含准确分组、Seed/ID及选择位置；成功且有变化才记历史，新编辑清空redo，失败和无变化不吞掉历史。覆盖当前参数加入、空白/来源分组、编辑、复制、移除与排序。历史仅限本次打开的队列编辑，开始生成和新建批次清空；429期间禁用，核心已开始分组保护保留，不恢复请求/计费/结果状态。

底部独立撤销/重做按钮，右键与操作菜单共用动作；Ctrl+Z、Ctrl+Y/Ctrl+Shift+Z、Ctrl+A、Ctrl+D、Delete、Esc；列表上下/Home/End/Shift扩选，Enter编辑，选中项滚动可见。参数弹窗使用独立焦点，列表快捷键不挂入输入框。

只用合成资料，不操作日常工作区、不真实生成，Prompt对比PENDING。初始编译验证期间追加了历史回归与列表焦点标记，初始阶段不作冻结证据；最终提交后的稳定源码回归与发行证据另补。

用户随后确认正常停止不得主动漏收已发送请求，最终规则覆盖中途的“立即停止”方案：暂停让当前图收完后PAUSED、可继续；结束批次让当前图收完后ENDED、不可直接继续，未发任务不再发送。结束意图随批次提交，重开优先对账已存结果；结果未知或429仍进入人工错误暂停。取消等待仅留异常菜单并确认风险。停止设置使用齿轮图标，正常结束为独立按钮。

已结束批次不能通过撤销或直接编辑复活；出现429后结束也不能直接恢复，归档新建仍需冷却期结束且人工操作。异常取消恢复使用已记录结果/429码及Retry-After，不能把已知429降为可跳过的未知错误。

首轮5项执行通过但运行期有追加源码，不作为冻结通过。第二轮4通过、1旧取消等待夹具因额度缓存未再次触发订阅请求而超时；旧普通取消方案随后被用户明确替代，保留失败，不作PASS。新慢响应测试将验证结束后仍保存响应及不发第二条。
