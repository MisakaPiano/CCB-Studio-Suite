# 大资产备份恢复边界修复

基线 `00064bbe52f327bc0ba112d8a44d105cef1750dc`，继续功能分支 `feature/windows-rc-continuous`，不改 AssetStore/A1/R1 安全核心。

发现并实际复现：资产核心允许单项256 MiB，整册ZIP/PDF可超过图片的32 MiB解码预算，但StudioRestore把全部备份文件按图片上限读取，导致33 MiB的合法合成ZIP无法恢复。修复前测试实际FAILED，原因是 `File exceeds budget; retained`，原工作区和备份没有被删除。

修复将备份清单及恢复核验改为64 KiB缓冲流式SHA-256与实际字节计数，资产沿用既有256 MiB上限，文档仍限4 MiB。恢复在建立目标前验证全部文件；文档复制时再次核对字节，资产核心继续独立校验其清单/发布。没有放松图像尺寸/解码限制，没有增加256 MiB以上的大对象支持。更新交接也改为流式核验资产，避免为大型整册生成第二份完整内存副本；快照内容和hash语义不变。

合成测试核对33 MiB ZIP的备份、恢复、重新打开和完整字节hash；同备份篡改后必须失败且不发布目标，原工作区原件继续通过校验；精确边界和超过预算保全文件。定向恢复/归档/维护12项实际PASS；补充缺失文件和非文件错误分类后，完整核心与受影响维护回归120项实际PASS，0失败/错误/跳过，212.722秒，源码稳定。桌面其余UI沿用前检查点196项完整结果，不冒称本轮重新执行。无真实图库、凭据或API访问，无安装或真人验收；现有DPAPI测试只用合成测试凭据。

JDK17.0.20.1、Gradle9.1.0，离线依赖严格验证、单worker、低资源执行。日志、失败、源码身份与测试结果见 `evidence/UX_LARGE_ASSET_RECOVERY`。此处修复不等于完整更新/数据迁移已通过；保持 PRODUCT_HOLD / NOT RC，继续数据读取能力与实际更新故障门槛。所有精简证据入Git，无新Drive附件。
