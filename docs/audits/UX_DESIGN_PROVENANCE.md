## 明确的设计关联

应用候选时，使用原 Desktop `applyDesignedPromptPlan` 语义；把本轮及此前对话、选中轮、应用前后 Prompt 保存为不可变资产。之后的对话不被混进早先候选。撤销/重做同步追踪显式应用关系；应用后手动编辑仍显示最后一次明确应用的候选，并明确提示最终内容有修改。不按相近时间、相同 Prompt 或当前账号设置猜测来源。

`StateJournal` 只增加现有提交链的只读投影：最近实际改变 CreationState 的提交摘要。不修改磁盘 Envelope、StudioState、GenerationReceipt 格式或原事务算法。关联资产绑定精确提交摘要及 CreationState 内容摘要；无关文档提交不改变身份，未被记录的写入使新草稿来源成为未知，不回退到旧关系。普通未应用 AI 设计的草稿不写空关联资产。

保存顺序是先保留候选、再提交现有草稿、最后写关联凭据。注入草稿已提交后的中断时，草稿及孤立候选保留，但新草稿不会被误报为已核验来源；这不是多文件原子事务，也不宣称任意断电目录持久化。生成前先保存设计关联到精确 job/Recipe/request SHA，再发布排队任务和访问网络。整批使用启动时冻结的应用引用，不受结果返回时继续设计影响。未知版本、冲突或摘要不符拒绝关联；已核验的原图/Recipe 仍可单独读取。

界面分“应用与生成”和“设计过程”，可以分别查看候选、应用后草稿与最终生成内容；复制按钮注明来源。操作只读取/复制，不发送 AI。设计记录保留选中回复中的目标图像模型；没有补造历史 LLM 模型或账号快照。旧图片未记录的关联继续标为未记录。

## 跨工作台的源图追溯

`ImageOrigins` 只跟随不可变资产中已记录的单图派生关系，最多128层并拒绝循环/冲突/未知格式。优先使用最近明确生成记录；该记录损坏时不回退到更早的有效记录。合成/局部重绘结果必须确实追溯到同一任务原结果才能取得对应 Seed。TypeSet 导出图通过已有来源快照/父图关联回到原生成图片；图库 Prompt、参照板请求快照及历史复用共用这一查询。

界面明确显示“来源图片的生成记录”和“当前图包含后续处理”，不会把原图参数冒充编辑后图的完整生成说明。PNG 内嵌参数同样只作为图片参数，不能升级为完整请求证据。多个来源合并到一张图的自动解释、非标准提供者后处理任务的完整源图链、缺失历史 LLM 账号快照尚未覆盖；不对这些情况猜测。
