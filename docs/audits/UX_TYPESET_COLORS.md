# TypeSet 富文本颜色兼容与错误恢复

基线 `d80acf68828fbbb1204dc6fedb2e6e0dd5011f6e`，继续 `feature/windows-rc-continuous`；未修改参考项目或资产安全核心，不代表最终产品验收。

固定 TypeSet Forge 1.1 的 `parseInlineTagToStyle` 原样保存 color/fill/stroke 值，再由 Canvas 解析。Suite 原先只接受3/6位HEX，其他值在富文本中被静默替换为上一样式。这使合法色名和半透明颜色不能按源行为呈现。本次增加148个标准色名、transparent、3/4/6/8位HEX、RGB/RGBA、HSL/HSLA、HWB，包含百分比、透明度、角度单位、现代空格语法与旧逗号语法；渲染、属性字段和导出共用解析器。

原富文本值继续保留，不为验证颜色而改写文本。布局只处理文字几何，颜色在渲染阶段验证；非法/暂不支持的写法会让预览显示明确错误并阻止成功导出，用户仍可修改文字，不再沿用旧颜色冒充成功。属性输入未合法时保留已有工程值并显示“尚未应用”。颜色空间 lab/oklab/display-p3、相对色、系统色/currentColor 等不在本轮实现范围，明确提示原值保留，不能声称已实现浏览器全部CSS颜色语法。

## 独立来源对照

`tools/Capture-TypeSetColors.cjs` 在隔离无界面Edge新上下文读取固定参考（SHA `892ea08f0070bdfd264b8895d38f6239f32f436b68a74ab42a2ef3336e28bb63`），仅做已记录的初始化次序修正及暴露原解析器，不改参考原件/解析算法；页面网络全部阻断。148个色名数值是标准事实表，初始由本机Pillow整理，逐个经独立浏览器核验；脚本现在读取随仓库保存的数据表，可复现。标准说明：[W3C CSS Color 4](https://www.w3.org/TR/2026/CRD-css-color-4-20261020/)。

实际取得162组原解析器与Canvas输出，包括148色名及透明度/函数组合。Core测试验证原文不被替换、透明度和渲染结果；不透明/白底通道容差1，半透明比较预乘通道容差1，并单独验证白底合成。浏览器与Java2D的8位预乘取整不同，直接解回RGB会放大低透明度误差：`#1234` 的原始测量分别为 `[15,34,49,68]`、`[19,34,53,68]`。该失败保留，没有改动原参考输出或宣称跨引擎像素完全相同。
